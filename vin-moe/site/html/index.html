platform
01

cluster

One Talos node. Control plane and worker, same physical server (allowSchedulingOnControlPlanes). No managed Kubernetes underneath. The node is provisioned out-of-band; Terraform bootstraps it with the siderolabs/talos provider and stores the resulting kubeconfig as state.

02

registry

Self-hosted Harbor on the same cluster. This site gets its own harbor_project. Pushes and pulls go through a CI robot account whose password is a Terraform random_password — never typed by hand — packaged into a dockerconfigjson secret and mounted as an imagePullSecret.

03

ingress & tls

ingress-nginx runs as a DaemonSet with hostNetwork: true, bound to the node's public IP. No load balancer. Each domain has its own cert-manager ClusterIssuer solving via DNS-01 against Cloudflare. Zone SSL mode is strict, so TLS is independently valid on both hops: browser→edge and edge→origin.

the site
04

image

Two-stage Dockerfile. Stage one is Alpine + imagemagick, converting the source PNG into a multi-resolution favicon.ico (16/32/48/64). Stage two is a pinned nginx:1.29-alpine with nginx.conf, the static HTML, and the favicon copied in. The single server block layers a security-header set (HSTS, CSP, nosniff, frame-deny, referrer policy), a /healthz endpoint, and gzip on top of a try_files fallback that redirects unknown paths back to /.

05

deployment

Two replicas behind a ClusterIP Service. 50m CPU / 16Mi requested, 200m / 64Mi limit. Startup, readiness, and liveness probes all hit /healthz. Rollouts surge to 100% with zero unavailable plus a pre-stop drain, and a PodDisruptionBudget keeps at least one replica serving. A VerticalPodAutoscaler in Auto mode tunes the memory request in that band; CPU is left unmanaged.

06

mirror

A second job rsyncs two things to a public GitHub repo via a scoped token: the site source into site-image/ and the workflow file into github-workflow/. It commits only if something changed. Source lives in two places — the private infra monorepo where it's built, and a public read-only mirror.

07

dns & cdn

vin.moe's A record points at the node's IP through a proxied Cloudflare record. Combined with DNS-01, none of Let's Encrypt's validation traffic reaches the origin — the only thing that must be reachable is the origin's own valid cert, and only Cloudflare needs to see it. The proxy also acts as the CDN: a Terraform-managed cache ruleset tells Cloudflare's edge to cache everything on this hostname — HTML included, not just static assets — so most requests never touch the origin at all.

node & security
08

the node

Dedicated hardware running Talos Linux — an immutable, API-driven OS with no shell, no SSH, and no package manager; every change goes through its config API, not a login. The ephemeral and state partitions are both LUKS2-encrypted. A host-level ingress firewall defaults to deny, with public web traffic accepted only from Cloudflare's published edge ranges — so the origin quietly ignores direct scans and floods.

09

defense in depth

Public traffic terminates at Cloudflare and is re-encrypted to the origin — strict SSL, independently valid on both hops — with HSTS and a content-security policy on every response. Administrative surfaces sit behind Authelia two-factor; the SSH VPS (debian pod deployed on cluster for remote dev) is reachable only over a private WireGuard mesh, never the public internet. In-cluster secrets are generated by Terraform and held in HCP Terraform, never committed to the repo, and CI runs on a namespace-scoped token rather than cluster-admin. Workloads run least-privilege under Pod Security Standards — the one exception is the CI runner pods (privileged, for docker-in-docker), so a Cilium NetworkPolicy scopes their egress to DNS and the outside world, blocking direct pod-to-pod reach into every other namespace: Harbor's internals, momus, Authelia, netbird.

10

watch & recover

A Prometheus / Grafana / Loki / Tempo stack watches the node and every workload. Persistent volumes back up nightly to encrypted object storage on rolling retention, and dependency bumps land automatically through Renovate with a human gate on majors.

ci/cd runners
11

actions-runner-controller

gha-runner-scale-set, deployed on the same cluster. containerMode is dind — every runner pod gets its own dockerd sidecar rather than mounting the node's docker socket, so concurrent jobs never share daemon state or root-level host access. minRunners is 0: no idle pool, every job gets a pod created fresh against whatever the current scale-set spec is.

12

the runner image

A custom image on top of the stock actions-runner base, with the toolchain every workflow needs pre-baked in — docker CLI, gh, jq, rsync, kubectl, tflint, actionlint, build-essential — so jobs stop apt-get installing the same packages on every single run. Built by its own workflow and pushed to a dedicated Harbor project. A scheduled scan runs daily against it; anything at CRITICAL or HIGH severity triggers an automatic rebuild.

13

registry access from runner pods

registry.vinnel.cloud stays Cloudflare-proxied for public traffic, but Cloudflare's proxy caps request bodies — too small for this image's own base layer. Runner pods carry a pod-level hostAliases entry routing straight to the node's own hostNetwork-bound ingress instead, paired with a host firewall rule opening 80/443 to the pod network (previously Cloudflare-edge-only). The BuildKit builder container spun up by a push needs its own network=host setting to inherit that same routing — a plain docker login and an actual image push resolve the registry hostname through completely different network paths.

deploying vin.moe
14

wait for infra

A push to the site's path on prd (or a manual dispatch) blocks first on that exact commit's Terraform run finishing successfully. A site never deploys against infra that hasn't reconciled yet.

15

pin the digest

After buildx pushes :latest and the commit SHA, the immutable sha256 digest — not the mutable tag — gets merged into a shared image manifest and committed. Concurrent deploys retry through a fetch/rebase/push loop rather than queuing behind a GitHub concurrency lock: a lock was tried first, but its one-pending-job-per-group limit silently dropped a third simultaneous deploy instead of letting it wait its turn. Bot-authored commits don't fire GitHub's own push events, so the same job explicitly re-triggers the Terraform run for that commit rather than leaving it to trigger itself.

16

roll out & purge

kubectl set-image to that exact digest, then a wait on rollout status — Terraform reconciles the same pinned reference on its next run, so the imperative rollout and the declared state never drift apart. Cloudflare's cache is purged only once the new pods are confirmed serving, so the CDN never re-caches the build that's on its way out.
