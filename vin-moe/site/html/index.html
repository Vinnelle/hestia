platform

  1. the node

    Talos Linux on dedicated hardware. No shell, no SSH, no package manager — every change is a declarative machine config applied over an mTLS API. Ephemeral and state partitions are LUKS2. Boot media comes from an Image Factory schematic pinned by content hash, and the installer image has to be that same schematic; point it at the stock one and Talos drops every extension at disk-write time.

  2. cluster

    One node, control plane and worker (allowSchedulingOnControlPlanes). Terraform generates the machine secrets, applies the config, bootstraps etcd, and holds the resulting kubeconfig in state.

  3. network

    Cilium replaced Flannel. Flannel accepts NetworkPolicy objects and never enforces them, which is worse than rejecting them. Cilium enforces in eBPF and adds identity-based policy, so a rule can select the node’s own host identity — a CIDR ipBlock never matches it, whatever the arithmetic says. Hubble’s flow UI sits behind SSO.

  4. storage

    local-path is the default class, for small sqlite-backed volumes. Rook Ceph runs across three disks for anything replicated, failure domain set to osd rather than host — one node, so disks are the only fault boundary that exists — with encryption at rest handled by Ceph.

  5. ingress & tls

    ingress-nginx as a DaemonSet on hostNetwork, bound to the node’s public IP. No load balancer. Per-domain cert-manager ClusterIssuers solve DNS-01 against Cloudflare, and every zone is strict SSL, so TLS is independently valid on both hops: browser→edge and edge→origin.

  6. registry

    Self-hosted Harbor on the same cluster, one project per site. Pushes and pulls go through a robot account whose password is a Terraform random_password — generated, never typed — mounted as an imagePullSecret.

the site

  1. the image

    Four build stages, every base pinned by sha256. One rasterizes the source PNG into a multi-resolution .ico and an apple-touch icon. One compiles ngx_brotli against the exact nginx version of the base image, since upstream ships no compatible release. One builds the assets. The last is nginx-unprivileged, running non-root.

  2. assets

    The webfont is fetched at build time and self-hosted, so nothing third-party loads at runtime and the CSP stays default-src 'self'. CSS and JS are minified, renamed to include a hash of their own contents, and every reference rewritten — which is what makes a one-year immutable cache safe rather than a guess. Everything text-shaped is pre-compressed once: gzip -9, brotli -q 11.

  3. serving

    nginx serves those pre-compressed files directly, so the runtime never spends a cycle compressing per request. Hashed assets get immutable cache headers and open_file_cache keeps hot descriptors around. Every response carries HSTS, CSP, nosniff, frame and referrer policy. /healthz is plaintext for the probes; .html URLs redirect to their extensionless form.

  4. the page itself

    No framework, no bundler, no runtime dependency. One document with its CSS and JS inlined; the font is the only other request. Themes are one palette through light-dark() rather than two copies of every token, so the toggle flips a single property. The numbers you’re reading are a CSS counter. Tabs are a real ARIA tablist — arrow-key navigation, deep-linkable by fragment, animated by the View Transitions API where it exists and plain where it doesn’t — and with JS off the nav hides itself and every panel renders instead.

  5. deployment

    Two replicas behind a ClusterIP Service. 50m/16Mi requested, 200m/64Mi limit. Non-root, every capability dropped, no privilege escalation, RuntimeDefault seccomp. Startup, readiness and liveness probes hit /healthz. Rollouts surge to 100% with zero unavailable plus a pre-stop drain, a PodDisruptionBudget keeps one replica serving, and a VerticalPodAutoscaler tunes memory inside that band.

  6. dns & cdn

    A proxied Cloudflare A record points at the node. Because certificates are issued over DNS-01, no ACME validation traffic ever reaches the origin — only Cloudflare needs to see its cert. A Terraform-managed cache ruleset caches everything on this hostname, HTML included, so most requests never reach the cluster.

  7. mirror

    After a successful deploy, a job rsyncs the site source and its workflow to a public GitHub repo through a scoped token, committing only if something changed. Private monorepo to build from, public mirror to read.

hardening

  1. the front door

    Talos host firewall, default deny. 80/443 accept only Cloudflare’s published edge ranges, so scans against the origin IP are dropped before nginx sees them. The Kubernetes and Talos APIs stay world-reachable on purpose: both are certificate-gated with no password surface, CI and Terraform have no pinnable egress IPs, and the Talos API is the recovery path for the firewall itself.

  2. defense in depth

    Admin surfaces sit behind Authelia 2FA. The dev box is reachable only over a self-hosted WireGuard mesh, never the public internet. Secrets are Terraform-generated and live in state, never the repo. CI authenticates with a token scoped to patching Deployments in one namespace. Workloads run under Pod Security Standards; the exception is the runner pods, which need privileged for docker-in-docker, so a Cilium policy limits their egress to DNS and the internet and blocks pod-to-pod reach into every other namespace.

  3. supply chain

    Base images, Actions and providers are pinned by digest or lockfile, so a moved tag can’t change what ships. Every push runs terraform fmt, tflint, go vet and tests, shellcheck, yamllint, actionlint, and gitleaks over full history. Trivy scans the runner image on a schedule and anything critical or high triggers a rebuild. Renovate raises the version bumps.

observability

  1. signoz

    One ClickHouse-backed stack for metrics, logs and traces, replacing Prometheus/Grafana/Loki/Tempo — four things to run and correlate by hand, now one. An OpenTelemetry collector discovers targets by pod annotation, so a new workload becomes observable by adding two labels, with no scrape config to edit. ingress-nginx exports OTLP spans, so a slow request and the logs behind it are one trace.

  2. alerting

    Alert rules are Terraform resources, not clicks in a UI: backup failure, node NotReady, PVC over 85%, certificate under 14 days, workload below desired replicas. They fan out to self-hosted ntfy and to Slack, renotifying every 4h while still firing. Dashboards go through the same API. What none of it can do is report its own death — a single node that stops answering stops alerting too, so that check belongs somewhere else.

  3. chaos & recovery

    Chaos Mesh kills a random site pod every 30 minutes and stresses one hourly, which is what keeps the disruption budget and probes above honest. Scoped to the websites namespace only — never auth, the mesh, or the alerting meant to catch it. restic snapshots the volumes nightly, encrypted and deduplicated client-side so object storage holds only ciphertext, on 7-day rolling retention with an integrity check each run.

ci/cd runners

  1. actions-runner-controller

    gha-runner-scale-set on the same cluster: CI runs on the node it deploys to. containerMode is dind, so every runner pod gets its own dockerd rather than mounting the node’s socket, and concurrent jobs never share daemon state or root-level host access. minRunners is 0 — no idle pool, every job gets a fresh pod against the current spec.

  2. the runner image

    Custom image on the stock actions-runner base with the toolchain pre-baked — docker, gh, jq, rsync, kubectl, tflint, actionlint, build-essential — so jobs stop apt-get installing the same packages every run. Each workflow’s install step was already guarded, so they became no-ops the day it landed.

  3. registry access from runner pods

    registry.vinnel.cloud stays Cloudflare-proxied for public traffic, but the proxy caps request bodies below this image’s own base layer. Runner pods carry a hostAliases entry routing straight to the node’s ingress, paired with a firewall rule opening the web ports to the pod network. BuildKit needs network=host on top of that: it runs in its own container with its own DNS, so docker login and the actual push resolve the same hostname through different paths.

deploying vin.moe

  1. wait for infra

    A push to the site’s path on prd waits only if that commit’s Terraform run is still mid-flight, purely to avoid racing an apply. Advisory, not a success gate: the deploy is imperative against an already-committed digest, and Terraform reconciles the same reference on its next run either way.

  2. pin the digest

    buildx pushes :latest and the commit SHA against a registry-hosted layer cache, so unchanged stages — the compiled nginx module included — are pulled, not rebuilt. The sha256 digest it returns, not the mutable tag, is merged into a shared image manifest and committed. Concurrent deploys retry through fetch/rebase/push: a GitHub concurrency lock was tried first, and its one-pending-job limit dropped a third simultaneous deploy outright instead of queuing it. Bot commits don’t fire push events, so the job re-triggers Terraform explicitly.

  3. roll out & purge

    kubectl set image to that exact digest, then wait on rollout status. Terraform reconciles the same pinned reference next run, so the imperative rollout and the declared state converge instead of drifting. Cloudflare’s cache is purged only once the new pods are serving — purge first and the CDN re-caches the build on its way out.
