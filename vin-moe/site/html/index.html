platform

  1. the node

    Talos Linux on dedicated hardware. No shell, no SSH, no package manager — every change is a declarative machine config applied over an mTLS API. Ephemeral and state partitions are LUKS2. Boot media comes from an Image Factory schematic pinned by content hash, and the installer image has to be that same schematic; point it at the stock one and Talos drops every extension at disk-write time.

  2. cluster

    One node, control plane and worker (allowSchedulingOnControlPlanes). Terraform generates the machine secrets, applies the config, bootstraps etcd, and holds the resulting kubeconfig in state.

  3. network

    Cilium as CNI, enforcing NetworkPolicy in eBPF, with identity-based policy on top — a rule can select the node's own host identity, something a CIDR ipBlock can never match. Hubble's flow UI sits behind SSO.

  4. storage

    local-path, the only class on the cluster — host-path volumes provisioned per pod, which is what a single-node box actually has to offer. No separate replicated pool: on one node there's no second fault domain for replication to buy anything.

  5. ingress & tls

    ingress-nginx as a DaemonSet on hostNetwork, bound to the node’s public IP. No load balancer. Per-domain cert-manager ClusterIssuers solve DNS-01 against Cloudflare, and every zone is strict SSL, so TLS is independently valid on both hops: browser→edge and edge→origin.

  6. registry

    Self-hosted Harbor on the same cluster, one project per site. Pushes and pulls go through a robot account whose password is a Terraform random_password — generated, never typed — mounted as an imagePullSecret.

the site

  1. the image

    Four build stages, every base pinned by sha256. One rasterizes the source PNG into a multi-resolution .ico and an apple-touch icon. One compiles ngx_brotli against the exact nginx version of the base image, since upstream ships no compatible release. One builds the assets. The last is nginx-unprivileged, running non-root.

  2. assets

    The webfont is fetched at build time and self-hosted, so nothing third-party loads at runtime and the CSP stays default-src 'self'. CSS and JS are minified, renamed to include a hash of their own contents, and every reference rewritten to match — that's what the one-year immutable cache header is keyed against. Everything text-shaped is pre-compressed once: gzip -9, brotli -q 11.

  3. serving

    nginx serves those pre-compressed files directly, so the runtime never spends a cycle compressing per request. Hashed assets get immutable cache headers and open_file_cache keeps hot descriptors around. Every response carries HSTS, CSP, nosniff, frame and referrer policy. /healthz is plaintext for the probes; .html URLs redirect to their extensionless form.

  4. the page itself

    No framework, no bundler, no runtime dependency. One document with its CSS and JS inlined; the font is the only other request. Themes are one palette through light-dark(), so the toggle flips a single property. The numbers here are a CSS counter. Tabs are an ARIA tablist with arrow-key navigation, deep-linkable by fragment, animated by the View Transitions API where it exists and plain where it doesn't. With JS off, the nav hides and every panel renders.

  5. deployment

    Two replicas behind a ClusterIP Service. 50m/16Mi requested, 200m/64Mi limit. Non-root, every capability dropped, no privilege escalation, RuntimeDefault seccomp. Startup, readiness and liveness probes hit /healthz. Rollouts surge to 100% with zero unavailable plus a pre-stop drain, a PodDisruptionBudget keeps one replica serving, and a VerticalPodAutoscaler tunes memory inside that band.

  6. dns & cdn

    A proxied Cloudflare A record points at the node. Because certificates are issued over DNS-01, no ACME validation traffic ever reaches the origin — only Cloudflare needs to see its cert. A Terraform-managed cache ruleset caches everything on this hostname, HTML included, so most requests never reach the cluster.

  7. mirror

    After a successful deploy, a job rsyncs the site source and its workflow to a public GitHub repo through a scoped token, committing only if something changed. Private monorepo to build from, public mirror to read.

hardening

  1. the front door

    Talos host firewall, default deny. 80/443 accept only Cloudflare’s published edge ranges, so scans against the origin IP are dropped before nginx sees them. The Kubernetes and Talos APIs stay world-reachable on purpose: both are certificate-gated with no password surface, CI and Terraform have no pinnable egress IPs, and the Talos API is the recovery path for the firewall itself.

  2. defense in depth

    Admin surfaces sit behind Authelia 2FA. The dev box is reachable only over a self-hosted WireGuard mesh, never the public internet. Secrets are Terraform-generated and live in state, never the repo. CI authenticates with a token scoped to patching Deployments in one namespace. Workloads run under Pod Security Standards; the exception is the runner pods, which need privileged for docker-in-docker, so a Cilium policy limits their egress to DNS and the internet and blocks pod-to-pod reach into every other namespace.

  3. supply chain

    Base images and Terraform providers are pinned by digest or lockfile, so a moved tag can’t change what ships. Every push runs go vet and tests, shellcheck, yamllint, and gitleaks over full history; terraform fmt and tflint run in front of the plan they gate. Trivy scans the runner image on a schedule and anything critical or high triggers a rebuild. Renovate raises the version bumps, grouped so a dozen digest bumps arrive as one reviewable merge request instead of a dozen pipelines, and majors wait for a human.

observability

  1. signoz

    One ClickHouse-backed stack for metrics, logs and traces. An OpenTelemetry collector discovers targets by pod annotation, so a new workload becomes observable by adding two labels, with no scrape config to edit. ingress-nginx exports OTLP spans, so a slow request and the logs behind it are one trace.

  2. alerting

    Alert rules are Terraform resources, not clicks in a UI: backup failure, node NotReady, PVC over 85%, certificate under 14 days, workload below desired replicas. They fan out to self-hosted ntfy and to Slack, renotifying every 4h while still firing. Dashboards go through the same API. A single node that stops answering also stops alerting — that failure mode has to be caught from outside the cluster, not by anything running on it.

  3. chaos & recovery

    Chaos Mesh kills a random site pod every 30 minutes and stresses one hourly, exercising the disruption budget and probes above against real failures rather than assumptions. Scoped to the websites namespace only — never auth, the mesh, or the alerting meant to catch it. restic snapshots the volumes nightly, encrypted and deduplicated client-side so object storage holds only ciphertext, on 7-day rolling retention with an integrity check each run.

ci/cd runners

  1. gitlab runner, kubernetes executor

    Two gitlab-runner Deployments live in-cluster, both the Kubernetes executor, no shared docker socket: a general runner (concurrent 4, untagged jobs land here) and a second runner that only picks up jobs tagged privileged-build, so an ordinary lint or test job can never land on a pod carrying privileged: true. Each job gets its own pod built from whatever image it declares — no dind, no daemon surviving between jobs to leak state. Runner config is a Secret; a config-hash pod annotation restarts the Deployment the moment it changes.

  2. the runner image

    Custom image on the stock actions-runner base with the toolchain pre-baked — docker, gh, jq, rsync, kubectl, tflint, actionlint, build-essential — so jobs stop apt-get installing the same packages every run. Pods pull it on every start rather than trusting a cached tag: with one node and a mutable :latest, the kubelet otherwise keeps the first copy it ever saw and silently ignores every rebuild, including the ones the vulnerability scan triggers. That makes the tag load-bearing, so a rebuild is smoke-tested — every baked binary actually runs — before it is allowed to become :latest. A broken runner image takes CI down and CI cannot fix it.

  3. registry access from runner pods

    registry.vinnel.cloud stays Cloudflare-proxied for public traffic, but the proxy caps request bodies below this image’s own base layer. The hostAliases entry routing straight to the node’s ingress lives on the runner’s own executor config, not the job — every job pod inherits it regardless of which image it declares, paired with a firewall rule opening the web ports to the pod network. BuildKit and kubectl end up resolving the same hostname the same way, from the same pod.

deploying vin.moe

  1. prove it builds

    A merge request touching a site runs the shared build-script test suite: the asset-hashing and cache-busting logic every site’s build.sh has in common gets exercised against a synthetic page, so a change to that shared logic is provable without touching the registry. Nothing else starts: the infrastructure plan skips the paths Terraform demonstrably never reads, so editing HTML no longer queues an apply on the one node that also serves the page.

  2. build & pin the digest

    buildctl pushes :latest and the commit SHA against a registry-hosted layer cache, so unchanged stages — the compiled nginx module included — are pulled, not rebuilt. The sha256 digest it returns, not the mutable tag, is merged into a shared image manifest and committed by the job that built it. On a push race the retry re-merges onto whatever landed first rather than replaying a fixed commit: sites deploying at once write neighbouring lines of the same JSON file, and a rebase would hit the identical conflict on every attempt until it gave up.

  3. roll out & purge

    The rollout reads the digest back out of git at the remote tip — deploy what was recorded, not what a job variable remembered. Then kubectl set image to that exact digest and wait on rollout status. Cloudflare’s cache is purged only once the new pods are serving — purge first and the CDN re-caches the build on its way out.

  4. reconcile & mirror

    Terraform apply only needs the digest-recording step, not the rollout — both read the same committed image manifest, so the imperative kubectl rollout and the declarative apply converge on the identical reference no matter which finishes first. Commits authored by CI push with the project’s job token, which GitLab excludes from triggering a new pipeline by default; a [skip ci] marker on the commit is belt-and-braces, in case that credential ever changes. The public mirror syncs last.
